# Kubernetes — Elisa IMS and EPC as separate services (lab, k3s)

Charts: [`deploy/k8s/charts/epc`](../../deploy/k8s/charts/epc), [`deploy/k8s/charts/elisa-ims`](../../deploy/k8s/charts/elisa-ims).
Driver: [`deploy/k8s/lab.sh`](../../deploy/k8s/lab.sh). Compose labs stay as they are; this is the split deployment.

## Shape

| Namespace | Workload | Replicas | Infinispan | Notes |
|-----------|----------|---------:|------------|-------|
| `epc` | `epc-hss` (HSS/AuC) | 1 | LOCAL (own `epc-hss-cluster` when DIST) | S6a toward `mme` |
| `epc` | `epc-sgwc` | 2 | `epc-sgwc-cluster` DIST_SYNC | S11 Service `sessionAffinity: ClientIP` |
| `epc` | `epc-pgwc` | 1 | `epc-pgwc-cluster` DIST_SYNC | Gx server for the PCRF |
| `epc` | `epc-pcrf` | 1 | LOCAL | dials every PGW-C pod (Gx client) |
| `epc` | `epc-up` | 1 | LOCAL | PFCP / GTP-U, `NET_ADMIN` |
| `epc` | `epc-postgres` | 1 | — | EPC DB only |
| `elisa-ims` | `pcscf`, `icscf`, `hss` | 1 each | LOCAL | Cx icscf ↔ hss |
| `elisa-ims` | `scscf` (pod = S-CSCF + FreeSWITCH) | 2 | `elisa-cluster` DIST_SYNC | FS 1:1 by construction, ESL / xml_curl on localhost, FS SIP on :5080 |
| `elisa-ims` | `nginx-edge` | 1 | — | SIP L4 VIP (hash $remote_addr) + admin, `LoadBalancer` |
| `elisa-ims` | `coturn`, `elisa-postgres` | 1 | — | |

- **One Infinispan cluster per role.** In compose every EPC process joined `epc-cluster`, so SGW-C state was
  replicated synchronously to the PGW-C (and back). On k8s each role has its own cluster name; `epc-*` never
  joins `elisa-cluster` (guarded in `EpcInfinispanManager`).
- **Discovery:** JGroups `kubernetes` stack (TCP + DNS_PING) on the role's headless Service
  (`publishNotReadyAddresses: true`). Env `EPC_CLUSTER_JGROUPS_STACK=kubernetes` /
  `SF_CLUSTER_INFINISPAN_JGROUPS_STACK=kubernetes` + `-Djgroups.dns.query=<name>-hl.<ns>.svc.cluster.local`.
  Unset = Infinispan's UDP multicast stack (compose, unchanged).
- **Addresses:** every NF has `<name>` (ClusterIP — GTP-C / PFCP peers; replies come back through the
  Service's conntrack) and `<name>-hl` (per-pod DNS `<name>-N.<name>-hl` — Diameter peers, DNS_PING).
  `EPC_LOCAL_ADDRESS=$(POD_IP)` (F-TEID, PFCP Node ID).
- **TEID / SEID partition** = `nodeIndexBase + pod ordinal`, unique inside the role's cluster.
- **Diameter peers by name** — Corsac matches a server-side link on the client's *IP* and a client link keeps
  dialling the address it resolved at start; a pod gets a new IP on every restart. micro-jainslee `ra-diameter`
  re-resolves name-configured peers every `peerRefreshMs` (default 10 s) while their link is not OPEN and
  re-creates the link (`CorsacPeerDnsRefreshTest`). Init containers wait for the peer pod's DNS name, which
  exists as soon as the pod has an IP.
- **nginx upstreams** use `server … resolve` (nginx ≥ 1.27.3) — the compose lesson "nginx resolves upstream names
  once" does not apply here.
- **Secrets** are generated by `lab.sh up` straight into the cluster (`epc-db`, `elisa-db`, `elisa-lab`); the
  charts only reference them. The ESL password is read from `freeswitch/conf/autoload_configs/event_socket.conf.xml`
  so FS and the S-CSCF agree.
- FreeSWITCH config is a ConfigMap built from `freeswitch/conf` (external profile moved to :5080, xml_curl to
  `127.0.0.1:8088`, vanilla `internal*`/`external-ipv6` replaced by `disabled.xml`).

## Run

```bash
./tools/package-dist.sh && (cd epc && mvn -pl epc-host -am package -DskipTests)
# once, as root: sudo systemctl start k3s && sudo install -d -o $USER /var/lib/rancher/k3s/agent/images
deploy/k8s/lab.sh images        # build + hand images to k3s (imagePullPolicy: Never)
deploy/k8s/lab.sh up            # helm install epc + elisa-ims, waits for Ready
deploy/k8s/lab.sh epc-attach 20 # in-cluster MME harness, pcap loadtest/pcaps/k8s/epc-attach.pcap
deploy/k8s/lab.sh ims-call      # SIPp via the nginx LoadBalancer, pcap loadtest/pcaps/k8s/ims-call.pcap
deploy/k8s/lab.sh down          # helm uninstall (PVCs kept); stop k3s when done
```

## Limits (lab)

- One PCRF: `ra-diameter` takes at most one server-role peer per RA, so each PGW-C lists `epc-pcrf-0` once.
- No MME / eNB in the cluster: srsRAN + open5gs MME stay in docker (interop scope); S11 is exercised by the
  in-cluster `MmeS11` harness behind the `mme` Service.
- RTP: FreeSWITCH media and coturn relay ports are pod-internal; signalling-only calls from outside. A media lab
  needs `hostNetwork` coturn or a UDP range on the node.
